# Исправление и улучшение фильтра по ключевым словам (`morphe-patches`)

## 1. Почему старый патч скрывал почти все видео (кроме плейлистов и Shorts)
В оригинальном `KeywordContentFilter` / `BufferPhraseFilter` было сразу несколько критических проблем:
1. **Поиск по «сырому» бинарному protobuf-буферу (`byte[] buffer`) вместо видимого текста**:
   - Для каждого обычного видео в ленте YouTube передает огромный protobuf-буфер (4–15 КБ), внутри которого лежат **данные предзагрузки плеера (`inlinePlayback`)**, ссылки `googlevideo.com/initplayback?...`, подписи превью `?sqp=...&rs=...`, 11-символьные `videoId`, Base64-ключи `entityKey` и бинарные токены аналитики `clickTrackingParams`.
   - У плейлистов и Shorts в ленте нет этого массивного блока `inlinePlayback`, поэтому они почти не попадали под ложные срабатывания.
   - Короткие слова вроде `"ai"`, `"AI"`, `"ИИ"`, `"ии"`, `"РКН"`, `"ркн"` (всего 2 буквы!) практически со 100% вероятностью встречались внутри многокилобайтных Base64-строк, ссылок и бинарных полей каждого обычного ролика.
2. **Ошибка проверки границ целого слова (`keywordMatchIsWholeWord`)**:
   - Метод проверял только `!Character.isLetter(codePoint)`. Если внутри Base64-ключа или ID видео комбинация `ai` или `AI` стояла рядом с цифрой (`0-9`), символами `_`, `-`, `/`, `+`, `=` или невалидным UTF-8 байтом (`null`), фильтр считал это «целым словом» и скрывал видео.
3. **Баг смещений UTF-16 vs UTF-8 в `phrasesWillHideAllVideos` и `getUtf8CodePointAt`**:
   - В `phrasesWillHideAllVideos` символьный индекс `String.indexOf` и длина в `char` (UTF-16) передавались в метод, ожидающий байтовые смещения UTF-8, что ломало проверку кириллических строк.
4. **Отсутствие `lockup.e` в `startsWithFilter`**:
   - Новая карточная верстка YouTube (`lockup.eml`) не была добавлена в список базовых контейнеров.

## 2. Что исправлено и добавлено

### Извлечение только реального видимого текста (`ProtoNode`)
- Вместо слепого поиска байтов по всему бинарному буферу, `KeywordContentFilter` теперь разбирает структуру protobuf через `ProtoNode.parse(buffer)` и извлекает **только читаемые пользовательские строки** (название видео, имя канала, `@handle` канала, строку метаданных, текст комментария и `accessibility`-описание).
- Автоматически пропускаются:
  - Блоки команд `innertubeCommand` (`169495254`), содержащие `inlinePlayback`, `clickTrackingParams`, `watchEndpoint`, `serializedShareEntity` и эхо поискового запроса (из `browseEndpoint` аккуратно извлекается только `@handle` канала);
  - Любые URL (`http://`, `https://`, `/vi/`, `googlevideo.com`, `ytimg.com`, `ggpht.com`);
  - Названия шаблонов Litho (`*.eml`, `*|hex`), шрифты (`YouTubeSans`), кодеки (`OMX.*`, `c2.*`), Base64 `entityKey`, `UC...` ID каналов и 11-символьный `videoId` самого ролика.
- В `BufferPhraseFilter.isWordCodePoint` границы целого слова теперь учитывают буквы, цифры, `_` и комбинируемые диакритические знаки Unicode.

### Нечувствительность к регистру по умолчанию + переключатель регистра
- По умолчанию поиск теперь **регистронезависимый (case-insensitive)** для любых языков (включая кириллицу и латиницу). Больше не нужно дублировать `"ai"` / `"AI"`, `"ИИ"` / `"ии"`, `"РКН"` / `"ркн"`, `Роскомнадзор` / `роскомнадзор`!
- При желании строгий учет регистра можно включить переключателем **«Учитывать регистр символов»** (`morphe_hide_keyword_content_case_sensitive`) или флагом `/шаблон/c` в регулярном выражении.

### Оператор `AND` (`&`)
- Поддержка объединения нескольких условий в одной строке через `&` (настройка **«Использовать оператор 'AND' ('&')»**, включена по умолчанию):
  - Например: `"обзор" & "ии"` или `@wylsacom & нейросет` — ролик скроется только тогда, когда в карточке присутствуют **все** части правила.

### Полноценная поддержка регулярных выражений (Regex)
- Поддерживаются три способа записи регулярных выражений (при включенной опции **«Использовать регулярные выражения (Regex)»**):
  1. В слешах: `/шаблон/` или `/шаблон/флаги` (`i` — без регистра, `c` — с учетом регистра, например `/\b(ai|ии|gpt|claude|gemini|deepseek)\b/` или `/нейро(сет|нк)/`).
  2. С префиксом: `regex:шаблон` или `re:шаблон`.
  3. Напрямую: любая строка без внешних кавычек `"..."`, содержащая метасимволы регулярок (`\`, `(`, `)`, `[`, `]`, `|`, `^`, `$`, `*`, `+`, `?`, `{`, `}`), автоматически компилируется как `java.util.regex.Pattern`.
- При ошибке синтаксиса в регулярном выражении приложение не падает, а показывает понятное уведомление с указанием некорректного правила.

### Режим отладки (Дебаг-режим: затухание вместо скрытия + показ сработавшего правила)
- В настройках фильтра появился переключатель **«Режим отладки (затухание вместо скрытия)»** (`morphe_hide_keyword_content_debug`):
  - Вместо удаления/скрытия видео и комментариев они остаются в ленте, но **вся карточка видео (превью, аватарка, текст) затухает (затемняется на ~66%)** и обводится тонкой акцентной рамкой.
  - В левом верхнем углу карточки рисуется контрастная плашка **`Фильтр: <сработавшее правило>`**, а перед текстом заголовка или комментария добавляется бейдж **`[<правило>]`**, чтобы сразу было видно, какое именно правило или регулярка сработала.
  - При прокрутке ленты и переиспользовании `ComponentHost` (RecyclerView) затухание и плашка автоматически снимаются с карточек, которые не подпадают под фильтр.

## 3. Список измененных файлов в архиве
Все файлы в архиве лежат по своим точным путям относительно корня репозитория `morphe-patches-main`:
1. `extensions/shared-youtube/library/src/main/java/app/morphe/extension/shared/patches/components/BufferPhraseFilter.java`
2. `extensions/youtube/src/main/java/app/morphe/extension/youtube/patches/components/KeywordContentFilter.java`
3. `extensions/youtube/src/main/java/app/morphe/extension/youtube/settings/Settings.java`
4. `patches/src/main/kotlin/app/morphe/patches/youtube/layout/hide/general/HideLayoutComponentsPatch.kt`
5. `patches/src/main/resources/addresources/values/youtube/strings.xml`
6. `patches/src/main/resources/addresources/values-ru-rRU/youtube/strings.xml`

Также в корне архива лежит файл `keyword-filter-fix.patch` — его можно применить одной командой в корне вашего форка:
```bash
git apply keyword-filter-fix.patch
```
Или просто распаковать папки `extensions/` и `patches/` поверх корня репозитория с заменой файлов.
